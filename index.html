One checker, different risk postures

Round 1 scored every response the same way. In practice a customer-facing chatbot, an internal copilot, and a regulated decision-support tool carry different latency budgets and risk tolerance — so Sentinel applies a different policy per use case, not one fixed threshold for everything.

Customer Support Bot
Real-time · customer-facing
Latency budget: <400ms
Risk tolerance: Low — auto-edit PII, block on any responsibility hit
Internal Copilot
Real-time · employee-facing
Latency budget: <1.5s
Risk tolerance: Medium — flag for review before blocking
Decision-Support Tool
Batch-tolerant · regulated workflow
Latency budget: <10s
Risk tolerance: Strictest — low bar to block, mandatory human sign-off

Tech stack

MOD.01

Anthropic Claude

Powers response generation and the resample-based semantic entropy check for the Performance lane. This prototype calls Claude directly from the browser with a bring-your-own key.

reasoning
MOD.02

NVIDIA NIM / Triton

Production path: the Responsibility classifiers and embedding models would run as NVIDIA NIM microservices on Triton Inference Server for low-latency, high-throughput serving at enterprise scale.

planned — production
MOD.03

Embeddings + Vector store

This prototype approximates semantic clustering with lightweight word-overlap. Production would swap in sentence-transformer embeddings and a vector store (e.g. Milvus) for real clustering at scale.

planned — production
MOD.04

Static frontend

Vanilla HTML, CSS and JavaScript — no build step, no framework. Runs from a single file so it's trivial to clone, open, and demo from any machine.
